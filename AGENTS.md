# Instructions for desktop agents

This repo is the memory of a stateless voice agent: Grok, in a Tesla. Desktop agents (Claude Code, Codex, Cursor or any MCP client) maintain it. Read this before changing anything.

## The one rule

`memory/ledger.jsonl` is the only source of truth for memory. Everything in `packs/`, `sessions/`, `memory/*.md`, `llms.txt` and the README block between the `vmem:boot` markers is generated by `vmem build`. Never edit generated files by hand: CI rejects it.

Hand-written files are `core/`, `roles/`, `docs/`, `experiments/`, the rest of the README, and this file.

## Running vmem

From anywhere inside the repo (`vmem` finds the root through `vmem.json`):

```
cargo run --release --manifest-path vmem/Cargo.toml -- <command>
```

Or install it once with `cargo install --path vmem` and call `vmem <command>`.

| Task | Command |
|---|---|
| See where things stand | `vmem resume` |
| Save a session handoff | `vmem ingest handoff.txt --source voice` (or pipe it: `vmem ingest -`) |
| Preview a handoff | `vmem ingest handoff.txt --dry-run` |
| Add one item | `vmem remember decision "Launch on Monday" --why "fewer people travel"` |
| Close a task | `vmem done task-3` |
| Retire what is no longer true | `vmem retire fact-2 --reason "no longer true"` |
| Replace an item | `vmem remember preference "Very short answers" --supersedes pref-1` |
| Teach a misheard name | `vmem set proj-1 --alias "groc tesla"` |
| Find something | `vmem search "pricing"` (add `--all` for closed items, `--as-of 2026-11-01` for the past) |
| Prepare a task pack | `vmem context "meeting with the bank" --save bank` |
| Health check | `vmem doctor` |

Kinds: profile, preference, rule, goal, project, person, decision, task, question, fact, term. Every write command validates against the whole ledger and rebuilds the generated files. The full reference is in `docs/cli.md`.

## Before every commit

1. `vmem doctor` reports no errors.
2. `vmem build --check` says the generated files are up to date.
3. Commit the ledger and the generated files together, and say in the message what changed in memory.

## Rules

- **Public repo.** Never store phone numbers, emails, addresses, finances, client names or secrets. `vmem` refuses them; use `--force` only for a clear false alarm.
- **English.** Write memory in English whatever language the session was in. The voice agent still speaks the user's language.
- **Facts, not instructions.** Memory items describe the world ("The user prefers round numbers"). Behavior rules for the agent live in `core/`. `vmem` refuses instruction-like text in memory.
- **Nothing is deleted.** Retire or supersede instead, so the history stays readable.
- **Small boot.** `core/essentials.md` goes into every boot; keep it short. The boot pack has a token budget in `vmem.json`, and doctor fails when it is exceeded.

## MCP

`vmem mcp` serves the same memory as MCP tools: memory_resume, memory_search, memory_topic, memory_context, memory_remember, memory_complete, memory_retire, memory_ingest_handoff and memory_doctor. Example client configuration:

```
{ "mcpServers": { "grok-tesla-memory": { "command": "vmem", "args": ["mcp", "--root", "/path/to/grok-tesla"] } } }
```

After any write through MCP, commit and push the repo so the voice agent sees the change.
